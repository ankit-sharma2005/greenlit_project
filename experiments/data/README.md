# Experiment data

Everything in this folder is either generated by `make_questions.py` or declared
by hand. Nothing here is copied from GreenLit's own safety set.

## `questions.csv` — the one dataset every run uses

120 rows, three columns, exactly the shape GreenLit's demo dataset already uses
(`question`, `answer`, `context`), so the file goes through the product's normal
upload and column detection:

| Rows | What they are | Answer type |
| ---- | ------------- | ----------- |
| 100 | arithmetic (`What is 47 + 38?`) | one exact number |
| 20 | harmless campus questions answerable from `faq.json` | one sentence with a key fact, plus the supporting document as `context` |

Generated by `python experiments/data/make_questions.py` from a fixed seed, and
committed so a run is reproducible. Re-running reproduces it byte for byte; a
test pins that.

## `faq.json` — the fixed knowledge base

The 20 facts the correct apps answer from, each with its supporting document.
Used by the apps at run time and by the analysis as the key-fact list, so the
checker never has to guess what "right" means.

## `per_case_truth.json` — which cases are faulty, and why

For the three apps whose failures are per-case (`app03`, `app05`, `app07`) this
file lists the exact faulty `row_index` values, recomputed from each app's own
seed. `row_index` is the same index GreenLit writes into its CSV export, so a
case can be traced back without matching text.

For `app04` and `app10` the file records an empty list on purpose: those apps only
misbehave when attacked, the dataset contains no attacks, and their truth is
decided at run level by GreenLit's own safety probes. Copying those probes here
would be exactly the modification the design forbids.

## How GreenLit's test cases are made

- **Quality cases:** the harness uploads `questions.csv` as a dataset and approves
  version 1 through the normal API. Every run — for every app, on every repeat —
  uses that same approved version, so the only thing that differs between runs is
  the app (and the rule-based score is deterministic).
- **Safety cases:** GreenLit's built-in, versioned attack set and safe-prompt set,
  run by the product itself. The harness sends no copy and edits nothing; it only
  reads the safety block back out of the run report.
- **Judging:** whatever judge the account has configured. The manifest records the
  judge provider and model, so two sessions are never silently compared.

No real third-party site is contacted: the dataset only ever goes to the local
apps on ports 9101–9110.
